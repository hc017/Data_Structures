Merge Sort

Divide the mess, sort the pieces, stitch them back together.

Day 18 Topic: Sorting Difficulty: Medium Pattern: Divide and Conquer Time: O(n log n) Space: O(n)

The Problem

Given an array of integers, sort it in ascending order in O(n log n) time.

Input : [38, 27, 43, 3, 9, 82, 10]
Output: [3, 9, 10, 27, 38, 43, 82]

The Story

Imagine a teacher with 100 unsorted exam papers. Sorting all 100 at once is exhausting. So she splits the pile in half and hands each half to an assistant. Each assistant splits again and hands it on, until every person holds a single paper. One paper is already sorted, nothing to do.

Now the magic: two people each holding a sorted pile combine them. They look at the top paper of each pile, take the smaller one, and place it on the new pile. Repeat until both piles are empty. Merged piles get merged again, all the way back up, and the teacher ends with one perfectly sorted stack.

Real-Life Example

Two supermarket queues, each already sorted by token number, are merged into a single counter line. The cashier simply compares the front of both queues and calls the smaller token. Databases do the same thing when sorting huge files: they sort chunks that fit in memory, then merge the sorted chunks (external merge sort).
