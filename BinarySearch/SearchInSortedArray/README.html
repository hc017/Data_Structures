Binary Search — Search in a Sorted Array

Day 14 · Topic: Binary Search · Daily DSA Challenge

Difficulty: Easy Pattern: Divide & Conquer Time: O(log n) Space: O(1)

The Problem

You are given a sorted array of distinct integers arr and a value target. Return the index of target in the array, or -1 if it is not there. 

Input:  arr = [2, 5, 8, 12, 16, 23, 38, 56, 72, 91], target = 23
Output: 5    // arr[5] == 23

Input:  arr = [2, 5, 8, 12, 16, 23, 38, 56, 72, 91], target = 40
Output: -1   // 40 is not present

The Story

Remember the number guessing game? A friend thinks of a number between 1 and 100 and you get to guess. If you guess 1, then 2, then 3, you may need 100 tries.

The clever player always guesses the middle. "Is it 50?" Your friend says "higher". Now you know the answer is somewhere in 51 to 100, so you instantly ignored 50 numbers. Next guess is the middle of that range: 75. "Lower." Another chunk gone.

Every guess cuts the possibilities in half, so even 1,000,000 numbers need only about 20 guesses. That is binary search. The only rule of the game: the numbers must be in order, otherwise "higher" and "lower" mean nothing.

Real-Life Example

Think of finding a word in a physical dictionary. You never start at page 1. You open the book around the middle, see you landed on words starting with "M", and since you want "S" you jump to the right half, open the middle of that, and repeat. Phone contact lists, version-control tools hunting for the commit that introduced a bug (git bisect), and database indexes all use the same halving trick.

Logic Flow Chart

Each pass either finds the target or halves the range, so the loop ends after about log2(n) rounds.

Approaches Compared

ApproachTimeSpaceIdea
Brute Force (linear scan)O(n)O(1)Look at every element until the target shows up
Binary Search (iterative)O(log n)O(1)Compare with the middle, discard the half that cannot contain the target
Binary Search (recursive)O(log n)O(log n)Same idea, each halving is a recursive call

Why it wins

1,000,000 elements need at most about 20 comparisons instead of 1,000,000.

Watch out

Needs sorted input. Use low + (high - low) / 2 to avoid integer overflow.
