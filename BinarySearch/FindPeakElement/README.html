Find Peak Element

Day 17 · Topic: Binary Search · Daily DSA Challenge

Difficulty: Medium Pattern: Binary Search on Slope Time: O(log n) Space: O(1)

The Problem

Given an array nums, find any index of a peak: an element strictly greater than its neighbours. Imagine the area outside the array is negative infinity, so the ends can be peaks too.

Input:  nums = [1, 3, 8, 12, 4, 2]
Output: 3   // nums[3] = 12 is greater than 8 and 4

The Story

You are hiking in thick fog and want to reach the top of a hill. You cannot see the summit, but you can feel the ground under your feet. If the ground slopes up in front of you, keep walking forward, because a summit must be ahead (the world ends in a drop, so the climb has to stop somewhere). If the ground slopes down in front of you, you are already at the top or have passed one, so a summit is here or behind you.

Binary search does this with jumps: stand in the middle, feel the slope, and throw away the half that cannot be your only option. Each step halves the trail.

Real-Life Example

Think of tuning a radio dial to find the clearest station. Turn the knob, and if the signal gets stronger as you move right, keep going right. If it gets weaker, the best signal is behind you. You never scan the whole band, you just follow the rising signal strength until it stops improving. Auto-tuning and hill-climbing optimizers use this same slope-following idea.

Logic Flow Chart

Both update branches return to the lo < hi check until the window shrinks to one index, which is a peak.

Approaches Compared

ApproachTimeSpaceIdea
Brute ForceO(n)O(1)Scan and compare each element with its neighbours
Binary Search (Optimized)O(log n)O(1)Follow the upward slope, halve the range each step

Why it works

An upward slope guarantees a peak ahead, because the array ends in negative infinity.

Trade-off

Returns one peak, not necessarily the highest one.
