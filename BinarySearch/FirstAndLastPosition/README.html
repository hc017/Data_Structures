First and Last Position of Element

Day 15 · Topic: Binary Search · Daily DSA Challenge

Difficulty: Medium Pattern: Binary Search (Boundary) Time: O(log n) Space: O(1)

The Problem

Given a sorted array nums that may contain duplicates and a target, return the index of the first and last occurrence of target. If it is not present, return [-1, -1].

Input:  nums = [1, 2, 2, 2, 3, 5, 5, 8], target = 2
Output: [1, 3]   // 2 first appears at index 1 and last at index 3

Input:  nums = [1, 2, 2, 2, 3, 5, 5, 8], target = 4
Output: [-1, -1]

The Story

Imagine a library shelf where books are sorted by ID and you want every copy of the book with ID 2. You open the shelf in the middle and find a copy of it. Great, but copies sit side by side, so this one might be in the middle of the group.

The slow way is to walk the whole shelf from the left end to the right end. The smart way is to run two searches. For the first copy, every time you find a hit you say "there might be an earlier one" and keep searching the left half. For the last copy, you say "there might be a later one" and keep searching the right half. Each search halves the shelf every step, so you finish in a handful of moves even with a million books.

Real-Life Example

A bank statement is sorted by date. To pull every transaction made on 14 March, you do not read the statement from page one. You jump to find the first entry of that date and the last entry of that date, then everything between them is your answer. Databases do this with indexes to answer range queries like WHERE date = '2026-03-14' quickly.

Logic Flow Chart

Run this loop twice: once biased left for the first index, once biased right for the last index.

Approaches Compared

ApproachTimeSpaceIdea

Two Binary SearchesO(log n)O(1)Do not stop at a hit, keep narrowing toward each edge

Why it wins

Sorted order lets us discard half the array every step.

Watch out

Use mid = lo + (hi - lo) / 2 to avoid integer overflow in Java.
