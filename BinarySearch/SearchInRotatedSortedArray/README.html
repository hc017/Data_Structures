Search in Rotated Sorted Array

Binary Search, but the array has been spun like a wheel.

Day 16 Medium Pattern: Modified Binary Search Time: O(log n) Space: O(1)

The Problem

A sorted array of distinct integers was rotated at some unknown pivot. Given a target, return its index, or -1 if it is absent. You must do it in O(log n).

Input : nums = [4, 5, 6, 7, 0, 1, 2], target = 0
Output: 4

Input : nums = [4, 5, 6, 7, 0, 1, 2], target = 3
Output: -1

The Story

Imagine a library shelf with books numbered 0 to 7 in order. A prankster picks up the first four books and moves them to the end, so the shelf now reads 4 5 6 7 0 1 2. You are hunting for book 0 and you may only peek at one book at a time.

You peek at the middle book: 7. Now compare it with the leftmost book, 4. Since 4 is smaller than 7, everything from the left end to the middle is still in perfect order. That is your sorted stretch. Is book 0 inside the range 4 to 7? No. So you throw away that whole stretch and search the other half. Next you peek at the middle of the remaining books, find 1, and repeat. Each peek halves the shelf, and the one fact you rely on is: one side of the middle is always sorted.

Rule of thumb: find the sorted half, ask whether the target lives in it, keep the half that could hold the target, drop the other.

Real-Life Example

A circular log buffer in a server, or a rotating shift schedule, stores timestamps in order but the start position drifts as old entries are overwritten. To find a given timestamp, the system does not scan every entry. It uses this exact trick: check which side of the midpoint is ordered, then narrow down. The same idea powers searches in ring buffers and in sorted data that has been wrapped around a start offset.
