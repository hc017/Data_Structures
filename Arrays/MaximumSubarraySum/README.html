Maximum Subarray Sum — Kadane's Algorithm

Day 2 · Topic: Arrays · Daily DSA Challenge

Difficulty: Medium Pattern: Kadane's Algorithm / DP Time: O(n) Space: O(1)

🧩 The Problem

You're given an array of integers nums that can include negative numbers. Find the contiguous subarray (at least one number) that has the largest sum, and return that sum. 

Input:  nums = [-2, 1, -3, 4, -1, 2, 1, -5, 4]
Output: 6   // because [4, -1, 2, 1] has the largest sum = 6

📖 The Story

Imagine you're tracking your daily profit/loss for a small stall over a few weeks — some days you gain money, some days you lose money. You want to find the best possible run of consecutive days that gave you the highest total profit.

The slow way: for every possible start day, add up every possible end day and compare. That means re-adding the same days again and again.

The smart way: walk through the days once, keeping a "current streak total" in your head. After each day, ask yourself — "is my current streak still worth continuing, or would I be better off starting a brand new streak from today?" If the streak so far has dragged you below zero, drop it and start fresh from today. Otherwise, keep riding it. All the while, remember the best streak total you've ever seen.

That "should I continue or restart" decision, made once per day, is exactly what Kadane's Algorithm does — no re-scanning, no nested loops, just one pass.

🌍 Real-Life Example

Think of a stock trading dashboard that highlights the best-performing consecutive trading window for a stock's daily gains/losses. Instead of comparing every possible date range against every other (painfully slow for years of data), the dashboard scans day by day, carrying forward a running streak and resetting it the moment it turns into a drag — instantly surfacing the best window as it goes. Same core idea powers GPS apps finding the "best stretch" of a route and fitness apps finding your best rolling-average pace.

Why Kadane's wins

Single pass through the array — each element is visited once, with only constant extra work.

Trade-off

None really — it's both faster and uses less memory than brute force, making it the clear choice here.
