Two Sum — Pair With Given Sum

Day 1 · Topic: Arrays · Daily DSA Challenge

Difficulty: Easy Pattern: Hashing Time: O(n) Space: O(n)

🧩 The Problem

You're given an array of integers nums and a target value target. Find the indices of the two numbers that add up exactly to target. 

Input:  nums = [2, 7, 11, 15, 1, 9], target = 9
Output: [0, 1]   // because nums[0] + nums[1] = 2 + 7 = 9

📖 The Story

Imagine you're at a coffee shop with exactly ₹90 in your wallet, split across a few loose notes on the table. You want to pick two notes that together add up to exactly ₹90 so you can pay without needing change.

The slow way: pick up any note, then check it against every other note on the table one by one. That's a lot of comparisons if there are many notes.

The smart way: as you look at each note, keep a mental note ("I've seen a ₹20 and a ₹50 so far"). For the note in your hand right now, just ask — "do I already remember seeing (90 minus this note's value)?" If yes, you found your pair instantly. If no, remember this note and move to the next one.

That "mental note" is exactly what a HashMap (Java) / dict (Python) does in this solution — it remembers numbers you've already passed, so you never have to look back and re-scan.

🌍 Real-Life Example

Think of a ride-share carpool matching app. Each rider has a "budget gap" they're willing to fill. The app wants to instantly pair two riders whose gaps add up to a shared trip's cost, without re-checking every single rider against every other rider each time someone new joins. Instead, it keeps a running lookup of gaps already seen, so a match is found the moment the right complement shows up — same trick as this problem.

🔀 Logic Flow Chart

Left branch loops back to "take next number" until either a match is found or the array is exhausted.

Why HashMap wins

One pass through the array instead of nested loops — each lookup is O(1) on average.

Trade-off

Uses extra memory to store seen numbers, trading space for speed.
