Next Greater Element

Day 7 · Topic: Stacks · Daily DSA Challenge

Difficulty: Medium Pattern: Monotonic Stack Time: O(n) Space: O(n)

🧩 The Problem

You are given an array nums. For every element, find the first element to its right that is strictly greater than it. If no such element exists, the answer for that position is -1. 

Input:  nums = [4, 5, 2, 25]
Output: [5, 25, 25, -1]
        // 4  -> 5 is the first bigger value to its right
        // 5  -> 2 is smaller, 25 is bigger  -> 25
        // 2  -> 25
        // 25 -> nothing to its right at all -> -1

Input:  nums = [13, 7, 6, 12]
Output: [-1, 12, 12, -1]

Input:  nums = [4, 3, 2, 1]
Output: [-1, -1, -1, -1]   // every value is bigger than everything after it

Note the word strictly: for [2, 2, 2] the answer is [-1, -1, -1], because an equal value does not count as greater.

📖 The Story

Picture a row of people standing in a queue, all facing forward (to the right). Each person wants to know one thing: who is the first person ahead of me who is taller than I am? That is the only person who blocks their view.

The lazy way is to ask each person to crane their neck and count heads one by one until they spot someone taller. That works, but a queue sorted tallest-first means everyone scans the entire line ahead of them. Enormous wasted effort.

So instead, walk the queue backwards, from the very last person to the first, carrying a small pile of notes — a stack. The pile holds the heights of people who are still visible from further back.

Now you reach a person of height h. Look at the top of the pile. Is that person shorter than or the same as h? Then throw that note away — forever. Nobody standing further back will ever see them, because this new person is closer and at least as tall, so they block them completely. Keep throwing away until the top of the pile is someone genuinely taller. That is the answer. If the pile empties out, nobody ahead is taller, so the answer is -1.

Finally, drop your own height on the pile, because you might be the blocker for somebody behind you. Then step back one place and repeat.

The pile is never in a random order: it always decreases from bottom to top, because anything smaller gets thrown away the moment a bigger value arrives. That is why this pattern is called a monotonic stack.

The magic is in the accounting. The inner “keep throwing away” loop looks like it could be expensive, but every height is written on the pile exactly once and thrown away at most once. Two operations per element, total — so the whole thing is O(n), not O(n²).

🌍 Real-Life Example

Stock prices. You hold a share and you want to know: after today, what is the next day the price closes higher than today? That is literally this algorithm running over a price series. Trading platforms compute this for entire histories in one pass rather than comparing every day against every later day.

Weather apps. “How many days until it gets warmer?” is the same problem asking for the index instead of the value — the well-known Daily Temperatures question.

Skyline visibility. An architect checking which buildings on a street still have an unobstructed view toward the horizon is discarding exactly the same shadowed candidates: a shorter building behind a taller one is invisible and can be forgotten.

🔀 Logic Flow Chart

The array is consumed from right to left. The inner pop loop discards shadowed candidates, and the stack stays decreasing from bottom to top at all times.

⚙ Approaches Compared

ApproachTimeSpaceIdea
Brute ForceO(n²)O(1) extraFor every index, scan forward until a strictly greater value appears; stop at the first one
Monotonic Stack (Optimized)O(n)O(n)Traverse right to left, popping every candidate ≤ nums[i]; the survivor on top is the answer

Why the stack wins

Each element is pushed once and popped at most once. Amortised, that is two operations per element regardless of how the inner while loop behaves on any single step.

Trade-off

You spend O(n) auxiliary space to buy back a factor of n in time. On a strictly decreasing array the brute force degenerates to a full O(n²) scan while the stack still finishes in one pass.

Edge cases worth remembering: an empty array returns an empty result; a single element is always -1; duplicates stay -1 because the comparison is strictly greater (use < instead of ≤ in the pop condition if you want equal values to count); and a strictly increasing array makes every answer the immediate neighbour.

💡 Where This Pattern Shows Up Next

Learn this skeleton once and a whole family of problems collapses into it: Daily Temperatures (same thing, return indices), Stock Span (mirror it to look left), Next Greater Element II (circular array — loop twice), Largest Rectangle in Histogram (find the nearest smaller bar on each side), and Trapping Rain Water. The only things that change are the direction of travel and whether the comparison is greater or smaller.
