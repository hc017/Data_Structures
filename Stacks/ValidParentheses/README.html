Valid Parentheses

Day 6 · Topic: Stacks · Daily DSA Challenge

Difficulty: Easy Pattern: Stack / LIFO Matching Time: O(n) Space: O(n)

🧩 The Problem

You are given a string s made only of the characters ( ) { } [ ]. Decide whether the brackets are balanced: every opening bracket must be closed by the same type of bracket, and they must close in the correct order. 

Input:  s = {[()()]()}
Output: true      // every bracket closes with its own partner, in order

Input:  s = ([)]
Output: false     // the ) tries to close a [ - wrong type, wrong order

Input:  s = (((
Output: false     // three brackets opened, none ever closed

📖 The Story

Imagine you are stacking dinner plates while washing up. Each time you open a bracket, you place a plate on the pile — a round plate for (, a square one for [, a fancy one for {.

Now someone hands you a closing bracket and says: put this one away. Here is the catch — you can only ever touch the plate on top of the pile. You cannot reach into the middle without the whole stack toppling.

So when a ) arrives, you look at the top plate. Is it round? Great — lift it off, they cancel out. Is it square instead? Then something went wrong: you opened a square bracket and are trying to close it with a round one. The string is invalid, and you can stop right there.

At the very end, the pile must be empty. If plates are still sitting there, you opened brackets you never closed.

That plate pile is exactly a Stack — ArrayDeque in Java, a plain list used with append and pop in Python. It is Last In, First Out: the most recently opened bracket is always the first one that must be closed.

🌍 Real-Life Example

Every code editor you have ever used does this. When VS Code greys out a stray } or highlights the matching bracket as your cursor moves, it is running this exact algorithm over your file. So is every compiler before it will even attempt to understand your program, and every HTML/XML parser checking that <div> tags close in the right order.

A less obvious one: the browser back button. Pages you visit are pushed onto a stack, and Back pops the most recent one. Same LIFO principle — the last thing you opened is the first thing you leave.

🔀 Logic Flow Chart

The loop keeps consuming characters. Any mismatch exits early with FALSE, and a leftover non-empty stack at the end also means FALSE.

⚙ Approaches Compared

ApproachTimeSpaceIdea
Brute ForceO(n²)O(n)Repeatedly delete adjacent pairs () [] {} until nothing changes; valid if the string becomes empty
Stack (Optimized)O(n)O(n)One pass: push opening brackets, and on a closing bracket check the top of the stack matches

Why the stack wins

Each character is pushed and popped at most once, so a single left-to-right pass is enough. The brute force has to rescan the whole string after every deletion.

Trade-off

Both use O(n) space in the worst case, so the stack is a straight upgrade here. It also fails fast, stopping the moment a mismatch is found.

Edge cases worth remembering: the empty string is valid; an odd-length string can never be valid; and a closing bracket arriving when the stack is empty is an immediate no.
