Detect Cycle in a Linked List

Day 10 · Topic: Linked Lists · Daily DSA Challenge

Difficulty: Easy–Medium Pattern: Fast & Slow Pointers Time: O(n) Space: O(1)

🧩 The Problem

You're given the head of a singly linked list. Determine whether the list contains a cycle — a point where some node's next pointer loops back to a node earlier in the list instead of eventually reaching null. 

Input:  3 -> 2 -> 0 -> -4 -> (back to node with value 2)
Output: true    // the list loops forever, it never reaches null

Input:  1 -> 2 -> 3 -> null
Output: false   // the list terminates normally

📖 The Story

Picture two runners on a circular running track: a slow jogger and a fast sprinter. Both start at the same point. The jogger takes one step at a time, the sprinter takes two.

If the track is actually a straight road that ends somewhere (no loop), the sprinter simply reaches the end and stops — they never see the jogger again.

But if the track loops back on itself, the sprinter will eventually come around and catch up to the jogger from behind, because the sprinter is gaining one extra step of distance every round. The moment they're standing on the same spot again, you know for certain the track is a loop — without ever needing a map of the whole track.

That's exactly Floyd's Cycle Detection Algorithm: the "slow" pointer moves one node at a time, the "fast" pointer moves two nodes at a time. If they ever meet, there's a cycle. If the fast pointer falls off the end (null) instead, there isn't.

🌍 Real-Life Example

Think of a version-control dependency graph or a chain of task redirects in a workflow engine (task A redirects to B, B to C, and so on). Before executing the chain, the system needs to make sure it doesn't loop back on itself and run forever — for example, task C accidentally redirecting back to task A. Walking the chain with a slow and fast pointer is a cheap, memory-free way to catch that infinite loop before it ever runs.

🔀 Logic Flow Chart

The pointers keep advancing (1 step / 2 steps) until either they land on the same node (cycle) or the fast pointer runs off the end (no cycle).

⚙️ Approaches Compared

ApproachTimeSpaceIdea
Brute Force (HashSet)O(n)O(n)Remember every visited node; a repeat means a cycle
Floyd's Tortoise & Hare (Optimized)O(n)O(1)Slow pointer +1, fast pointer +2 — they meet only if there's a loop

Why Floyd's wins

Same time complexity as the HashSet version, but uses no extra memory at all — just two pointers.

Trade-off

Slightly trickier to reason about than "remember what you've seen", but well worth it for O(1) space.
