Reverse a Linked List

Day 9 · Topic: Linked Lists · Daily DSA Challenge

Difficulty: Easy Pattern: Pointer Manipulation / Three Pointers Time: O(n) Space: O(1)

🧩 The Problem

You are handed the head of a singly linked list. Reverse it and return the new head. Every node knows only one thing — who comes next. There is no prev pointer to lean on, and no way to walk backwards.

The catch that makes this a real exercise: you must reverse it by re-pointing the existing arrows, not by copying the values into an array and pouring them back. Rewriting values is cheating the lesson; rewiring pointers is the lesson. 

Input :  1 -> 2 -> 3 -> 4 -> 5 -> null
Output:  5 -> 4 -> 3 -> 2 -> 1 -> null

Input :  7 -> 9 -> null          Input :  42 -> null        Input :  null
Output:  9 -> 7 -> null          Output:  42 -> null        Output:  null

Notice what the answer must contain: the old tail becomes the new head, and the old head becomes the new tail — so its next has to end up null. Forgetting that one detail is the classic way to build an infinite loop.

📖 The Story

Picture a paper treasure hunt through a school. Each classroom holds a single slip of paper, and the slip says only one thing: “go to the library next.” The library's slip says “go to the canteen next.” And so on, down a chain, until one room holds a slip that says “the end.” That chain of slips is a linked list. You can follow it forwards easily. Going backwards is impossible — no slip ever mentions where you came from.

Now the principal wants the hunt run in reverse. The last room should be the starting point, and the old starting room should hold the “the end” slip.

A nervous student would copy every room name onto a notepad, walk the list backwards on paper, then write a fresh slip for every room. It works. It also means carrying a notepad as long as the hunt itself.

A calm student walks the hunt once, carrying just three facts in their head: the room they just came from, the room they are standing in, and the room the current slip points to. In each room they do four small things, always in this order:

1. Read the slip and memorise where it says to go — this is the only moment that information exists. Overwrite first and the rest of the hunt is lost forever.
2. Rewrite the slip to point at the room they came from instead.
3. Remember that this room is now “where I came from”.
4. Walk to the room they memorised in step 1.

The very first room has nothing behind it, so its slip is rewritten to say “the end.” When the student finally steps out of the chain into nothing, the room they came from is the new start of the hunt.

One walk. Three facts in memory. No notepad.

Those three facts are the three pointers: prev, cur, next. The order of the four steps is the entire algorithm, and swapping steps 1 and 2 is the single most common bug in this problem — you cut the rope you are still standing on. 

prev = null                     cur = 1 -> 2 -> 3 -> 4 -> 5 -> null

step 1:   null <- 1              cur = 2 -> 3 -> 4 -> 5 -> null
step 2:   null <- 1 <- 2         cur = 3 -> 4 -> 5 -> null
step 3:   null <- 1 <- 2 <- 3    cur = 4 -> 5 -> null
step 4:   null <- ... <- 4       cur = 5 -> null
step 5:   null <- ... <- 5       cur = null   <-- stop, prev = 5 = new head

Read the left column as “already reversed” and the right column as “not yet touched”. The boundary between them slides one node per step, and the two halves are never broken at the same time — that is why the list is never corrupted mid-flight.

🌍 Real-Life Example

A train that has to go back. Carriages are coupled front-to-back, and each coupling only knows the carriage behind it. To send the train the other way you do not rebuild the train — you re-couple. The guard's van becomes the engine end, the engine end becomes the tail. Same carriages, reversed couplings, one pass down the platform.

A chain of email forwards. A message gets forwarded person to person, each one knowing only who they sent it to. To trace the thread from the last recipient back to the original sender, someone has to walk the chain once and flip every “sent to” into a “received from”.

Browser history, in the real implementation. A doubly linked list gives you Back and Forward for free precisely because it stores both directions. Reversing a singly linked list is what you are forced to do when that second pointer was never paid for — a neat illustration of the memory-versus-convenience trade.

Reversing a log of actions for undo. Any “replay these steps backwards” feature over a singly linked history is this exact operation.

🔀 Logic Flow Chart

Four statements, one loop, three pointers. The order of the four statements is the whole algorithm — reorder them and you either lose the tail or spin forever.

⚙ Approaches Compared

ApproachTimeSpaceIdea
Copy values to array (brute force)O(n)O(n)Walk the list collecting values, then build a brand new list from the values backwards. Simple, but allocates a second container and a second set of nodes.
Three-pointer iteration (optimised)O(n)O(1)One pass. Save next, flip cur.next to prev, slide both pointers forward. Nothing is allocated at all.
RecursionO(n)O(n) stackReverse the tail, then point head.next.next back at head and null out head.next. Elegant, but one stack frame per node.

Why iteration wins

Same O(n) time as the others but O(1) space and no allocation. It also mutates the list in place, which is usually exactly what the caller wanted.

Where recursion bites

One frame per node. A list of a million nodes overflows the stack — Python raises RecursionError well before that, at around a thousand. Fine for interviews, risky in production.

Edge cases worth remembering: an empty list must return null rather than crash — the loop simply never runs; a single node comes back unchanged; the old head must end with next = null, which happens for free because prev starts as null; reversing twice must return the original ordering, which is the cheapest correctness test you can write; and remember the caller's old head variable now points at the tail — always use the returned head.

💡 Where This Pattern Shows Up Next

This is the load-bearing subroutine for half of the linked list catalogue. Palindrome Linked List finds the middle, reverses the second half and compares. Reverse Nodes in k-Group and Reverse Linked List II are this loop applied to a slice. Reorder List is split, reverse, merge. Add Two Numbers II reverses both inputs to get least-significant digits first. The same save-then-overwrite discipline reappears in Flatten a Multilevel List, in swapping pairs, and in Floyd's cycle detection, where a careless pointer update silently invents a loop.
